# SHIMAI — セッションクローズ儀式

長い作業セッションの終わりは、**一番情報が濃く、一番失われやすい。**
「あれ、この前どこまでやったんだっけ」を毎回やらないための儀式。

口頭で毎回同じことを指示していたのを定型化したもの（51セッションの棚卸しで、
明示的な「ログ残して落として」だけで8回以上を確認した）。

## 手順（この順で）

1. **成果の洗い出し**
   このセッションで確定した **決定 / 学び / 作りかけ / 他人待ち** を列挙する。
   「やったこと」ではなく「**残す価値があること**」を選ぶ

2. **振り分け**（置き場所は下の表。自分の運用に合わせて書き換える）

   | 内容 | 置き場所 |
   |---|---|
   | 決定・学び・インシデント | `log/YYYY-MM-DD-<slug>.md` を新規作成 |
   | 継続作業・引き継ぎ | 既存の `<slug>-todo.md` か `projects/<name>/next-actions.md` を更新（完了した todo は冒頭に完了と明記） |
   | プロジェクトの事実 | `projects/<name>.md` |
   | 本人の判断基準・価値観の新発見 | **提案止まり。本人確認が要る。勝手に書かない** |

3. **索引更新**
   ファイルを足したら索引（`README.md`）に1行追記する。
   **忘れが最多の工程。** 索引に載っていないファイルは、次のセッションで発見されない

4. **memory**
   セッション限りでない事実・feedback があれば永続メモリに保存する。**重複チェックしてから**

5. **残ボール提示**
   「**次に誰が何をするか**」をチャットに3行以内で出して終了。
   自分のボールと他人待ちを分けて書く

## やらないこと

- **判断の要る棚卸し・大掃除**（疲れている終わり際にやると雑になる。別セッションで）
- 本人の価値観・判断基準ファイルへの無確認書き込み
- **手動 git commit**（自動コミットに任せる。壊れやすい大変更を入れた直後だけ例外的に即コミット可）

## 効く理由

セッションの終わりに「何が起きたか」を書くのは、**次の自分ではなく次のAIのため**。
AIは前回のコンテキストを持たない。索引と `log/` だけが引き継ぎ手段になる。

だから記録は**要約**でなく**決定と理由**を書く。何をしたかは差分を見れば分かるが、
なぜそうしたかはどこにも残らない。
